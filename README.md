# Finote — семейные расходы

Telegram-бот разбирает обычный текст с помощью LLM и работает только с расходами
отправителя. Веб-панель показывает расходы всей семьи и поддерживает CRUD через REST.
Бэкенд — Go, база — PostgreSQL 16, интерфейс — HTML/CSS/JavaScript, встроенные в Go-бинарник.
Требования задания: [test-task-expenses.md](test-task-expenses.md).

## Быстрый запуск

Нужен Docker с Docker Compose. Go и Node.js на компьютере для этого запуска не нужны.

1. Для новой копии проекта создайте настройки: `cp .env.example .env`.
   **Если `.env` уже есть, не перезаписывайте его.**
2. Для проверки только панели оставьте `TELEGRAM_BOT_TOKEN` пустым.
   Для бота заполните токен и параметры LLM, описанные ниже.
3. Запустите приложение и базу:

```bash
docker compose up -d --build
```

Откройте http://localhost:8080. Миграции применяются автоматически до запуска HTTP.
Пустой список при первом запуске нормален: демонстрационные расходы не создаются.
Данные сохраняются в Docker volume `postgres_data`.

```bash
docker compose logs -f app
docker compose down
```

Обычный `down` сохраняет расходы. Не используйте `down -v`, если данные нужно сохранить.
После изменения `.env` пересоздайте приложение: `docker compose up -d --force-recreate app`.

## Telegram и LLM

Создайте бота через Telegram @BotFather командой `/newbot` и перенесите токен в
`TELEGRAM_BOT_TOKEN`. Получите API-ключ у выбранного LLM-провайдера и укажите
доступную вашему аккаунту модель. Данные доступа не входят в репозиторий.

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен BotFather; пустое значение отключает бота |
| `TELEGRAM_TIMEZONE` | Часовой пояс относительных дат, по умолчанию `Asia/Almaty` |
| `LLM_BASE_URL` | URL OpenAI-совместимого API с его префиксом, без `/chat/completions` |
| `LLM_API_KEY` | Ключ провайдера |
| `LLM_MODEL` | Идентификатор доступной модели |
| `DB_DSN` | Подключение PostgreSQL; Compose заменяет localhost на сервис `postgres` |
| `APP_PORT` | HTTP-порт локального процесса, по умолчанию `8080`; в Compose оставьте `8080` |

Провайдер должен поддерживать `POST /chat/completions` с `response_format: {"type":"json_object"}`.
Для Gemini через совместимый API базовый адрес:
`https://generativelanguage.googleapis.com/v1beta/openai`.
Ключ и модель выбираются в Google AI Studio; конкретная модель не зашита в код.
Для другого совместимого провайдера укажите его адрес и модель.

Один токен — один запущенный polling-процесс. Существующий webhook приложение
самостоятельно не удаляет. Бот обрабатывает только личные текстовые сообщения.
Текст запроса отправляется LLM-провайдеру; ID владельца берётся из Telegram,
а не из ответа модели. Кандидаты из базы при уточнении в LLM не отправляются.

Примеры из задания:

```text
кофе 350
такси 1200 вчера
сколько потратил на еду в этом месяце
покажи траты за неделю
последнее было не 350, а 450
удали такси
```

При нескольких совпадениях бот просит выбрать запись: `2`, «первую», «вчерашнюю»,
«на 1200», «за 20.10.2026». Пока выбор активен, текст считается уточнением.
`отмена` или `/cancel` отменяет выбор, `/new` начинает новый запрос.
Контекст хранится 10 минут и переживает перезапуск.

## REST API и панель

Панель административная и **без авторизации**, как требуется в ТЗ.
Она видит все расходы. В Compose HTTP доступен только через `127.0.0.1`.
Не публикуйте приложение или базу в интернете без дополнительной защиты.

| Метод | Адрес | Результат |
|---|---|---|
| GET | `/v1/payments` | Список, итоги и пагинация |
| GET | `/v1/payments/{id}` | Одна трата |
| POST | `/v1/payments` | Создание, `201` |
| PATCH | `/v1/payments/{id}` | Только переданные поля, `200` |
| DELETE | `/v1/payments/{id}` | Удаление, `204` без тела |
| GET | `/v1/users` | Сохранённые ID участников, включая участников без расходов |
| GET | `/v1/users?details=true` | Объекты `{id, display_name, username?}` для панели |

Сохранён также PUT для клиентов, передающих все изменяемые поля.

Каждый расход содержит `version` (целое число от 1). PATCH принимает необязательный
`expected_version` вместе с изменяемыми полями. Например:
`{"comment":"кофе с собой","expected_version":3}`. Проверка версии и изменение
выполняются атомарно в SQL. При несовпадении — HTTP 409 с `code: "version_conflict"`,
без изменения расхода; для отсутствующей записи — 404; неположительная версия — 400.
Все обновления, включая Telegram и PUT, увеличивают версию. Старые клиенты без
`expected_version` продолжают работать, но не получают защиту от устаревшей записи.
Панель всегда передаёт версию и только изменённые поля; при конфликте сохраняет ввод
до явного обновления формы. Автоматического повторения PATCH нет.

Имена и необязательный username обновляются из проверенного отправителя приватного
сообщения Telegram. Они нужны только для отображения; доступ определяется Telegram ID.
Старые участники переносятся из расходов миграцией 005, новые запоминаются при создании
расхода или обращении к боту (включая /start). Удаление последней траты не удаляет
участника. Пока участник не напишет боту, неизвестное имя отображается как «Участник ID».
Профили доступны в той же открытой семейной панели; авторизация этим изменением не добавляется.
Фильтры списка: `user_id`, `category`, `from`, `to`, `timezone`, `limit`, `offset`.
`from` и `to` — календарные даты включительно в выбранном часовом поясе
(по умолчанию Алматы). `limit`: 1–100, по умолчанию 20.
Сумма `amount` в ответе списка — десятичная строка по **всей выборке**, не только странице.

Следующий запрос создаёт реальную запись в выбранной базе:

```bash
curl -sS http://localhost:8080/v1/payments \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"123456","amount":350,"category":"еда","comment":"кофе"}'
```

```bash
curl -sS -G http://localhost:8080/v1/payments \
  --data-urlencode 'user_id=123456' \
  --data-urlencode 'category=еда' \
  --data-urlencode 'from=2026-10-01' \
  --data-urlencode 'to=2026-10-31' \
  --data-urlencode 'limit=20'
```

В командах ниже замените `UUID` на `id` из ответа создания:

```bash
curl -sS -X PATCH http://localhost:8080/v1/payments/UUID \
  -H 'Content-Type: application/json' -d '{"amount":450}'
curl -i -X DELETE http://localhost:8080/v1/payments/UUID
```

Ошибки: `400` — неверные данные, `404` — трата отсутствует, `500` — внутренняя ошибка.
При таймауте API возвращает `503` с `code: "request_timeout"` и полем `error`.
Тело: `{"error":"описание"}`. Подробности внутренних ошибок остаются в логах.
Сумма положительная, до двух знаков после запятой; комментарий — до 500 символов.

Telegram ID перед сохранением и при фильтрации приводится к положительному
десятичному int64: `00123`, `+123` и ` 123 ` становятся `123`.
Ноль, отрицательные значения, дроби, текст и переполнение возвращают 400.
Пустой фильтр user_id по-прежнему означает всех участников.
В URL знак плюс передавайте как %2B (или используйте curl --data-urlencode).
Ранее сохранённые неканонические ID эта правка автоматически не меняет:
для них требуется отдельная проверка и согласованное исправление данных.

### Таймауты панели и REST

Для маршрутов /v1/ действует общий контекст на 5 секунд: он ограничивает
обработку запроса и запросы PostgreSQL, включая ожидание соединения/блокировки.
Дополнительный предел выдачи ответа — 8 секунд. HTTP-сервер ограничивает чтение
запроса 10 секундами, запись ответа — 12, простой соединения — 60.
Таймаут не гарантирует откат операции, если соединение оборвалось после её выполнения.

Клиент панели ждёт до 12 секунд, включая чтение тела ответа. Устаревший запрос
списка отменяется без сообщения об ошибке; реальный таймаут показывает ошибку.
Создание, редактирование и удаление никогда не повторяются автоматически.
При сетевой ошибке, таймауте, 5xx или некорректном ответе на изменение результат
считается неизвестным. Повторная отправка из этой формы блокируется, но окно
можно закрыть. Кнопка «Проверить список расходов» закрывает окно, сбрасывает
фильтры и выполняет только чтение. После проверки можно открыть форму заново.
Это защита от случайного повтора, не серверная идемпотентность POST.

Тесты клиента и состояния форм: `make test-web` (нужен Node.js с fetch и node:test,
например Node.js 22+). Они не требуют рабочей базы или настоящих токенов.
Go-тест с FINOTE_TEST_DATABASE_URL проверяет настоящий SQL-запрос под блокировкой:
API отвечает 503 примерно через 5 секунд, отложенная вставка не происходит.
Дополнительная HTTP-симуляция клиента:

    postman simulation run postman/simulations/panel-timeout.sim.yaml --port 4902 --output ndjson
    FINOTE_PANEL_SIM_URL=http://127.0.0.1:4902/panel make test-web

Первую команду оставьте в отдельном терминале. Mock воспроизводит задержку и
формат ошибки Finote; проверяется настоящий JS-клиент, не настоящий бэкенд.
Симуляция локальная, без публикации; mock создан из контракта текущего проекта.

## Тесты

Все проверки, включая настоящую PostgreSQL, детектор гонок и `go vet`, без Go на хосте:

```bash
make test-integration
```

Если `make` недоступен:

```bash
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose -f compose.test.yaml down
```

Тестовый Compose — отдельный проект `finote-tests`, без портов на хосте,
без `.env`, токенов и постоянных данных. PostgreSQL работает в tmpfs.
При первом запуске нужен интернет для загрузки образов и Go-модулей.

Для разработки с Go 1.25.12 или новее: `make test`.
Без `FINOTE_TEST_DATABASE_URL` интеграционные тесты пропускаются, поэтому для
приёмки нужен именно `make test-integration`. Не направляйте тесты в рабочую базу.

Текущие тесты проверяют атомарность расхода и исходящего ответа, конкурентную
повторную обработку, восстановление доставки, блокировку и порядок очереди,
ошибки Telegram 401/403/429/503, независимость панели от сбоя бота и health endpoints.
Telegram заменён локальными HTTP-серверами. Полного набора тестов CRUD, фильтров,
диалогов и качества распознавания LLM в текущей версии нет.

## Архитектура и миграции

- `internal/payment/service` — общие правила расходов для REST и Telegram.
- `internal/payment/repo` — SQL, фильтры и принудительная привязка к владельцу для бота.
- `internal/telegram` — разбор запросов, polling, уточнения и квитанции обработки.
- `internal/web` — встроенная веб-панель.
- `internal/migrations` — встроенные SQL-миграции, журнал и проверка контрольных сумм.

Миграции применяются транзакционно с блокировкой от одновременного старта.
Первая миграция принимает существующие таблицы прежней версии без удаления данных.
Применённые SQL-файлы не редактируются: добавляйте следующий файл с новым номером.
Автоматического отката схемы нет; перед изменениями рабочей схемы делайте резервную копию.
Расход, изменение диалога и квитанция Telegram коммитятся в одной транзакции.

## Проверка перед сдачей

1. Запустите проект с новой базой и собственными ключами.
2. Два пользователя добавляют траты в личных чатах бота.
3. Каждый проверяет, что видит только свои расходы.
4. В панели проверьте оба ID, фильтры и изменение суммы.
5. У соответствующего пользователя проверьте изменённую сумму через бота.
6. Создайте две одинаково названные траты и проверьте уточнение при удалении.
7. Перезапустите приложение и проверьте сохранность данных.

## Ограничения и безопасность

Валюта — тенге; панель показывает даты Алматы. Изменение `TELEGRAM_TIMEZONE`
меняет даты бота, но не часовой пояс панели. Сумма в Go представлена `float64`,
в PostgreSQL — `NUMERIC(14,2)`; это учебный учёт расходов, не платёжная система.
Бот показывает до 10 записей, сумма считается по всем совпадениям.
Диалог уточняет выбор существующей траты, но не хранит произвольную историю общения.

Защита от повторной мутации есть. Ответ сохраняется вместе с расходом в PostgreSQL
и доставляется отдельно из таблицы telegram_outbox, в том числе после перезапуска.
При аварии после принятия сообщения Telegram, но до отметки sent, ответ может
прийти повторно: доставка не является exactly-once. Сам расход не дублируется.
Распределённый запуск нескольких polling-процессов не поддерживается. Для LLM возможны ошибки сети,
лимиты и неточное распознавание; неоднозначные изменения не выполняются автоматически.

`.env` и настройки IDE исключены из Git, `.env` также исключён из Docker-образа.
Если ключ когда-либо публиковался, удаление файла из Git не заменяет отзыв ключа.
Сообщение `.env file not found` внутри Docker нормально: Compose передаёт настройки
через окружение. `password authentication failed` обычно означает несовпадение
учётных данных с уже инициализированным PostgreSQL volume; не удаляйте volume ради исправления.

Проект дорабатывался с ИИ-ассистентом: последовательно реализованы панель, REST,
валидация, уточнения и общий слой расходов, затем добавлены автоматические проверки.
Живую интеграцию с выбранной моделью и Telegram нужно проверить по сценарию выше.

## Независимость Telegram и панели

Временные ошибки polling/БД перезапускают обработчик бота через 3 секунды,
но не завершают HTTP-сервер. Неверная конфигурация бота, Telegram 401/409 или
настроенный webhook останавливают только бота. Причина пишется в лог;
после исправления настроек приложение нужно пересоздать. Ошибки запуска
основной БД, миграций и HTTP-сервера остаются критическими для приложения.

Исходящий ответ записывается одной транзакцией с расходом и квитанцией.
Фоновый отправитель делает один HTTP-вызов с таймаутом 10 секунд за попытку.
Сетевые ошибки и 5xx повторяются с растущей паузой до 256 секунд; 429 учитывает
retry_after. 400/403 отмечают ответ как failed без бесконечных повторов.
При 401 бот останавливается, ответ остаётся pending.
Захват задания действует 30 секунд: после аварии его можно забрать снова.
Порядок pending-ответов сохраняется внутри чата, отложенный чат не блокирует другие.
Отметки sent/failed сохраняются для диагностики; автоматическая очистка пока не добавлена.

Старые квитанции автоматически массово не рассылаются: для них задание создаётся
только при повторной доставке соответствующего update от Telegram.
При ошибке БД update не подтверждается и обрабатывается повторно после восстановления;
при недоступной БД надёжно сохранить сообщение об ошибке невозможно.
Параллельная обработка входящих сообщений по-прежнему ограничена текущей пачкой.

- GET /healthz: 200 — HTTP-процесс работает.
- GET /readyz: 200 — БД отвечает; 503 — БД недоступна (проверка до 2 секунд).
- Готовность относится к панели/API: недоступность Telegram или LLM не меняет её.
- Docker Compose проверяет /readyz. Сам по себе healthcheck не перезапускает контейнер.

Дополнительная локальная проверка очереди через Postman CLI:

    postman simulation run postman/simulations/telegram-outbox.sim.yaml --port 4901 --output ndjson

В другом терминале, с FINOTE_TEST_DATABASE_URL отдельной тестовой базы:

    FINOTE_TELEGRAM_SIM_URL=http://127.0.0.1:4901/telegram go test -run TestOutboxSimulation -v ./internal/telegram

Mock покрывает используемый формат sendMessage и ошибку 503, а не весь Telegram API.
Он создан из существующего клиента; поиск опубликованного mock пропущен, поскольку
локальная сессия Postman не авторизована. Настоящие токены и расходы не используются.

### Контекст Telegram

Бот сохраняет до 10 ID из последнего показанного списка отдельно для пользователя
и бота. «Покажи второй», «покажи 1», «измени второй на 700», «удали второй»
ссылаются на сохранённую запись, а не на текущую позицию в БД. Показ одной записи
по номеру не заменяет исходный список. «А id?» возвращает ID выбранной,
добавленной или изменённой записи. Владельца сервер заново проверяет в SQL.

Контекст живёт 10 минут после последнего обновления, переживает перезапуск,
но сбрасывается через /cancel, /new или /start. Если запись удалена или контекст
истёк, бот просит повторно показать список, не подставляя другую запись.

«Добавь кофе» может быть разобрано LLM как незавершённое создание: бот спрашивает
сумму, а следующий ответ «400» или «400,50» завершает операцию без LLM.
Неверная сумма сохраняет уточнение; /cancel отменяет его. Уточнение действует
10 минут. Пока оно активно, для другой команды сначала используйте /new.
Это ограниченный контекст, а не полная история переписки. Свободный текст
по-прежнему зависит от LLM; типовые ссылки на номера обрабатываются локально.

Миграция 004 создаёт таблицу контекста автоматически при запуске.
Тесты используют отдельную FINOTE_TEST_DATABASE_URL:

    postman simulation run postman/simulations/telegram-context.sim.yaml --port 4903
    FINOTE_CONTEXT_SIM_URL=http://127.0.0.1:4903/llm go test -race ./internal/telegram

Локальная имитация проверяет HTTP-формат Chat Completions и обработку новых
полей, но не качество понимания текста настоящей моделью.
